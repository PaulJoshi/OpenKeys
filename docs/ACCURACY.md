# Accuracy

_Generated by `npm run accuracy` on 2026-10-02 (OpenKeys 0.1.0)._

> **Read this first.** These numbers come from the automated test set: real Salamander Grand Piano recordings (the same samples the app plays) and a synthetic piano model, rendered offline and fed through exactly the code that runs in the AudioWorklet. The "laptop mic" condition is a *simulation*: a 150 Hz high-pass (small speakers), a 0.5 s reverberant room, pink-ish background noise and −12 dB gain. It is deliberately harsh, but it is not a real CT-S1 in a real room. Real-instrument numbers will be added per release from labelled takes recorded with the dev panel (mic + USB MIDI at the same time, MIDI as ground truth). Until then, treat the mic figures as a regression baseline, not a promise.

Metrics follow the standard transcription convention: a detection matches if the pitch is right and the onset is within 50 ms. The **false-wrong rate** is the share of correctly played notes that the judge would mark *wrong* (the number that matters most to a learner; "unsure" verdicts are not counted as wrong).

## Known weaknesses

- **Low notes through laptop speakers/mics.** Below about C3 the fundamental is mostly filtered out; detection leans on upper partials and the level rise. Fast repeated bass notes are the hardest case.
- **Fast passages over held bass notes** (e.g. the Minuet): eighth notes under reverb sometimes don't look "freshly struck"; the judge then says "?" rather than wrong, but recall drops.
- **Wrong-note detection in chords is conservative by design**: roughly half to two thirds of neighbouring-key slips are caught. The judge prefers missing a mistake to marking a correct note wrong.
- **Octave errors**: a played lower octave contains the expected note's partials. The octave-trap check uses the lower octave's odd partials, but octave doublings inside a chord cannot be told apart this way.

## How to reproduce

```sh
npm run accuracy      # needs ffmpeg for the Salamander renders
```

To add real-instrument data: open the dev panel (`?debug`), connect the keyboard by USB *and* enable the microphone, press **Record labelled take**, play, stop, then **Evaluate** (or download the WAV + JSON and add them under `tests/fixtures/takes/`).
